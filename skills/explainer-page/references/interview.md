# 독자 수준 인터뷰

목표는 자기 평가가 아니라 실제 이해 수준을 확정하는 것이다. AskUserQuestion은 한 번에 질문 4개, 질문당 선택지 4개까지라 라운드를 나눈다. 2~4라운드에서 개념이 4개를 넘으면 한 라운드를 여러 호출로 나눈다. 라운드마다 무엇을 확인했는지 한 줄로 알리고 다음으로 넘어간다.

## 0. 준비 (질문 전)

- 자료 수집에서 선행 개념 목록을 만들고, 개념마다 의존 관계를 붙여 층으로 나눈다: 기초(학부 수준 수학·ML 일반) → 중간(분야 표준 개념) → 직전(이 자료가 바로 기대는 개념).
- 같은 프로젝트에 다른 페이지 폴더가 있으면 그 `CLAUDE.md`의 `## 독자 수준` 기록을 모은다(예: `grep -l "## 독자 수준" */CLAUDE.md`). 같은 개념이 '아는 것'으로 기록돼 있으면 묻지 않고 '기록 재사용'으로 표에 넣는다. '애매'·'모름' 기록은 다시 묻는다(그 사이 배웠을 수 있다).

## 1라운드: 목적과 깊이

한 번의 AskUserQuestion으로 묻는다.

- 읽는 목적: 직관만 / 논문을 읽을 수 있게 / 직접 구현 / 남에게 설명.
- 수식 깊이: 각 항의 역할만 / 핵심 유도까지 / 전체 유도(`<details>`).
- 코드: 없음 / 핵심 줄 발췌 / 동작하는 최소 예제.
- 분량: 짧고 핵심만 / 보통 / 길어도 빠짐없이.

## 2라운드: 층별 자기 평가

- 아래 층부터 묻는다. 기초 층 개념을 '모름'으로 고르면 그 개념에 기대는 위 층 개념은 묻지 않고 '모름'으로 둔다.
- 질문 하나에 개념 하나, 선택지는 '설명할 수 있다 / 들어 봤다 / 처음 본다'. 선택지 description에 개념을 한 줄로 풀어 둬서 이름만 보고 오해하지 않게 한다.

## 3라운드: 확인 문제

- '설명할 수 있다'를 고른 개념 중 본문에 직접 쓰이는 것마다 객관식 확인 문제를 하나 낸다. 정의 암기가 아니라 적용을 묻는다(예: "temperature를 2로 올리면 가장 큰 확률은? 커진다 / 작아진다 / 그대로 / 경우에 따라 다르다").
- 오답 선택지는 흔한 오해로 만든다. 맞히면 '아는 것', 틀리면 '애매'로 내리고 어떤 오해였는지 기록한다.

## 4라운드: 막힌 지점

- '들어 봤다'(애매) 개념마다 어디가 막히는지 묻는다: 정의 / 직관(왜 필요한지) / 수식 / 다른 개념과의 차이.
- 답에 따라 복습 박스의 초점을 정한다.

## 5라운드: 확정

- 표로 보여 준다: 개념 | 층 | 수준(아는 것·애매·모름·기록 재사용) | 근거(자기 평가·확인 문제·기록) | 본문 반영(생략·`<details>` 복습·본문 설명).
- 목적·깊이 답과 함께 페이지 구성 개요(h2 주장 문장 목록)를 붙여 AskUserQuestion으로 '확정 / 수정'을 받는다. 수정이면 해당 라운드만 다시 한다.
- 확정되면 표와 1라운드 답을 페이지 폴더 `CLAUDE.md`의 `## 독자 수준` 섹션에 기록한다. 이 확정 이후는 묻지 않고 끝까지 진행한다(SKILL.md '자동 진행').
