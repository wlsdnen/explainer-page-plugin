# 스타일과 파일 구조 규칙

## 파일 구조

- 페이지 하나에 폴더 하나, 단일 `index.html`. CSS와 JS는 인라인, 빌드 단계 없음. 클립·이미지·vendored 라이브러리는 같은 폴더의 하위 폴더에 두고 상대 경로로 부른다.
- 계산 로직(수식·시뮬레이션)은 DOM을 건드리지 않는 `<script id="core">`에 두고, 그리기와 이벤트 연결은 두 번째 `<script>`에서 core를 읽어 처리한다. 이렇게 나눠야 `check.mjs`가 core만 떼어 Node에서 돌릴 수 있다.
- 폴더 `CLAUDE.md`에 페이지 구조와 `## 독자 수준` 섹션을 둔다. 배포할 때 `CLAUDE.md`와 `check.mjs`는 제외한다.
- 조각(head 없는 HTML)이 아니라 아래처럼 완전한 문서로 쓴다.

## head 필수 요소

```html
<!doctype html>
<html lang="ko">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>페이지 제목</title>
```

- `lang`(기본 `ko`, 출력 언어에 맞춤), viewport, `<title>`.
- `<title>`(브라우저 탭)과 첫 `<h1>`(검색 엔진·사이트 검색이 보는 제목)을 같은 주제로 맞춘다.

## 디자인은 콘텐츠에서 출발한다

- 색 팔레트·토큰 이름·글꼴·레이아웃·컴포넌트 모양을 미리 정해 두지 않는다. 페이지마다 주제의 성격에 맞춰 정한다. 예: 기하·공간 주제는 3D 그림 중심, 파이프라인 주제는 흐름도 중심.
- 기존 페이지의 디자인을 복사하지 않는다. 디자인은 장식이 아니라 내용 이해를 도와야 한다.

## 기능 요건

- 라이트 전용: 다크 색 블록을 만들지 않고 `:root`에 `color-scheme: light`를 명시한다. 페이지를 다크 테마 사이트에 넣거나 OS가 다크 모드여도 브라우저 기본 조작부·스크롤바가 어둡게 그려지지 않게 하기 위해서다.
- 색은 페이지 안에서 CSS 변수로 모아 관리하고, 그림과 글자도 그 변수를 쓴다. 변수 이름은 자유다.
- 출력 언어 글꼴이 깨지지 않게 글꼴 스택에 넣는다. 한국어 예: `-apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`.
- 375px에서 가로 스크롤이 없고 글자가 읽혀야 한다.
- 조작부(버튼·슬라이더)는 터치 대상이 최소 44×44px. 주된 조작부 묶음에 `data-widget` 속성을 달아 검사 스크립트가 찾게 한다.
