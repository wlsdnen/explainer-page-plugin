# 설명문 규칙

## 페이지 흐름

- 제목 + 한 줄 요약 → 섹션들 → 함정·오해 → 출처와 더 읽을거리.
- 섹션 제목(h2)은 주장 문장으로 쓴다. 예: "T는 순위를 바꾸지 않고, 간격만 바꿉니다".
- 섹션 안 순서: 무엇을 볼지 1~2문장 → 그림·애니메이션·클립 → 왜 그런지 짧게.
- 그림이나 예시가 먼저, 글은 최소로. 유도·예외·보조 자료는 `<details>`에 넣는다.
- '애매'로 기록된 선행 개념은 처음 쓰이는 섹션에 `<details>` 복습 박스로 둔다.

## 원리 설명

- 기술 원리는 직관적으로 이해되도록 풀어서 쓴다.
- 수식은 전체 유도를 따라가게 하지 않는다. 각 항(term)이 어떤 역할인지와 수식의 핵심 개념을 설명한다. 유도가 꼭 필요하면 `<details>`로 내린다.
- 페이지에서 직접 유도한 식은 유도라고 밝히고, 논문 인용처럼 쓰지 않는다.
- 데이터·모델·평가가 나오는 문서는 아래 흐름을 그림과 함께 설명한다.
  1. 데이터 정제 방법
  2. 입력/출력 포맷
  3. 입력이 모델 안에서 처리되는 방식
  4. 출력
  5. 손실과 학습 방식
  6. 평가 지표

## 코드 블록

- 이해에 도움이 될 때만 넣고, 전체 코드가 아니라 원리가 드러나는 줄만 발췌한다.
- 원리를 보여 주는 줄만 담은 `<pre><code>`와, 그 위의 "이 코드가 하는 일" 한 줄로 충분하다. 발췌 출처(저장소 파일·셀)를 코드 위에 적는다.
- 줄별 설명이 필요하면 코드 아래 `<ol>`에 "1-3행: ..." 식으로 단다.

## 문체와 용어

- 기본(한국어): 합쇼체(~입니다). 다른 언어면 그 언어의 정중하고 평이한 설명체를 쓴다.
- 한 문단 3문장 이내. 비유는 섹션당 최대 하나.
- 용어는 페이지 첫 등장 때 출력 언어 뒤 괄호에 영어를 쓴다. 덜 통용되는 번역어 대신 영어를 그대로 쓴다(loss, rollout).

## 숫자와 사실

- 모든 숫자에 꼬리표를 단다(출력 언어가 다르면 꼬리표도 번역한다).
  - `논문`: 논문 값. 표·그림 번호를 함께 적는다.
  - `블로그`: 기술 블로그·웹 페이지 값. 글 제목이나 섹션을 함께 적는다.
  - `강의`: 강의에서만 나온 값.
  - `계산`: 페이지에서 산술로 유도한 값.
  - `예시`: 설명용으로 만든 값. 측정값처럼 쓰지 않는다.
- 논문 주장·수치는 원문에서 확인한 것만 쓴다. 고치거나 더할 때도 원문을 다시 확인한다.
- 블로그·웹 페이지의 주장도 원문 페이지를 직접 열어 확인한다. 블로그가 논문을 인용하면 가능하면 논문(1차 출처)에서 확인하고 `논문`으로 표시한다.
- 논문 그림 속 값이 원래 예시라면 예시로 표시한다.
- 강의와 코드 저장소가 다르면 저장소 값을 쓰고 페이지에 그렇게 밝힌다. 자동 자막은 숫자가 깨지므로 원문과 대조한다.
- 장난감 시뮬레이션은 실제 모델과 다른 점을 페이지에 적고, 시뮬레이션을 바꿔도 그 안내를 유지한다.
